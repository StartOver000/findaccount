# 试师赛季区服数据源（自动更新）

> 调研时间：2026-10-25。结论：**试师区服可以自动、免登录获取**，来源是网易官方「告示板」H5 的 `teamData.json`。

## 1. 怎么获取当前哪些区服是试师（结论）

| 项 | 内容 |
| --- | --- |
| 数据文件 | `https://w.163.com/h5/stzb/gg/data/teamData.json`（官方 H5「告示板」数据，JSON 数组，约 539 行，持续更新，响应头 `Last-Modified` 即官方数据时间，小时级） |
| 页面入口 | `https://w.163.com/h5/stzb/gg/index.html#/` → 顶部页签「赛季预告」（大神 App：率土之滨 → 工具合集 → 告示板 → 赛季预告） |
| 识别规则 | 每行是一批开区/分区计划：`teamtime` 开启时间、`teamtype` 赛季类型、`teamid` 该批次区服 ID 列表。**`teamtype` 含「试师」的行，其 `teamid` 就是试师区服**，如 `百业争鸣(试师)` → `X6137,X6138,...,X6142` |
| 是否要登录 | 不需要。该 H5 免登录，也不依赖大神账号/藏宝阁会话 |
| 备用源 | `https://www.163hot.net/st/bulletin/v2/teamData/page`（POST `{"opt":{"page":0,"pageSize":200}}`，字段与静态 JSON 一致；主源失败时脚本自动回退） |

为什么之前找不到：藏宝阁的「区服选择」列表（`game_compete_server_list.js`，153 个当前开放区服）**不含试师标记**；大神网页版工具卡在未登录时点击无响应。但告示板是独立 H5，直接用它的静态数据文件即可。

### 关键字段示例

```json
{ "teamtime": "2026/10/25 12:00:00", "teamtype": "百业争鸣(试师)",
  "teamid": "X6137,X6138,X6139,X6140,X6141,X6142" }
```

## 2. 已落地脚本

```bash
npm run shishi          # 抓取并重写白名单（= node scripts/update-shishi.js）
npm run shishi:check    # 只抓取比对、不写文件（适合定时巡检/流水线前置检查）
node scripts/update-shishi.js --json   # 只打印 JSON
node scripts/update-shishi.js --force-api --check --allow-stale  # 仅排障：验证备用源是否可达
```

- 主源失败会回退 163hot 接口（最多 50 页 × 200 条）；但该接口已停更（见第 7 节），会被安全校验拦下；
- 解析为 0 条 / 不足 100 服 / 最新批次超过 60 天 → 报错退出（退出码 1），不会静默写残缺表（`--allow-stale` 仅排障用）；
- 写文件为原子写（临时文件 + rename），中断不会留下半截 JSON/MD；
- 输出的 `data/shishi-servers.json` 含 `ids`（全集）、`bySeason`（按批次，新→旧）、`lastModified`、`source`、`totalRows`；
- 同时输出 `data/shishi-open.json`：把试师白名单与藏宝阁当前开放区服（`game_compete_server_list.js`）求交集，得到**现在就能买到**的 65 个试师区服的 `openServerids`（供采集脚本直接用）；
- 另输出 `data/shishi-open-serverids.txt`（逗号分隔，方便命令行/其他脚本直接读取）；
- 统一读取入口 `scripts/lib-shishi.js`：`getServerIds()` 返回当前开放 serverid 串（文件缺失才回退 legacy），`getShishiIds()` 返回全量历史试师 ID；采集脚本不再各自内联兜底；
- 生成的白名单：`docs/试师赛季白名单.md`（给藏宝阁筛选用，含按批次列表 + 全部 ID）；
- `--quiet` 可静默（`find-all.ps1` 调用用）。

## 4. 旧手工白名单纠错（重要）

对 `git HEAD` 版 `docs/试师赛季白名单.md`（70 个区服）与官方数据比对：

- **误加 7 个**（官方试师表中不存在）：`X5781`-`X5785`（2026/06/25 建安风云，征服赛道，不是试师）、`X5829`、`X5830`（官方 teamData 中根本没有这两个区服）。旧表按区间 `X5773-X5791` 整段抄写导致混入征服服，会把建安风云的征服号当成试师号筛进来。
- **漏掉 766 个**：旧表只覆盖 2026-06 前后的少量批次，例如 `X4402-X4404`（2025/02/01 兵合车错(试师)）、`X5750-X5755`、`X5761-X5766` 等早期批次均缺失。
- 结论：以脚本生成的 `docs/试师赛季白名单.md` 为准，不要手改。

## 5. 刷新与集成（已接线）

- **定时刷新**：试师一般每 2-3 天开一批，每天跑一次 `node scripts/update-shishi.js` 足够。
- **Windows 任务计划**（每日 09:00 示例）：

```powershell
schtasks /Create /SC DAILY /ST 09:00 /TN "stzb-update-shishi" /TR "node D:\WorkSpace\率土之滨\scripts\update-shishi.js" /F
```

- **已接线的脚本**（统一经 `scripts/lib-shishi.js` 读 `data/shishi-open.json`，缺失才回退旧硬编码）：
  - `scripts/api-collect.js`（API 直采，主链路）；
  - `scripts/cbg-detail-extract.js`（浏览器列表采集的默认 URL）；
  - `scripts/page-list-collect.js`（DOM 列表采集）；
  - `scripts/collect.ps1`（参数化采集默认区服）；
  - `scripts/find-all.ps1` 在直采前自动执行 `update-shishi.js --quiet`。
- **重要发现（旧硬编码已失效）**：原先内联的 65 个 serverid（`44748`-`44874`）与当前藏宝阁开放试师区服**完全没有交集**，对应区服均已关闭；当前开放的是 `44966`-`45117` 区间。若继续用旧硬编码，采集会空转/采到已关服数据。现在由 `shishi-open.json` 自动刷新，且 `npm test` 会断言采集脚本不再残留旧硬编码。
- 旧代码里另有两处白名单（`scripts/legacy/find-accounts-20260807.ps1` 的 9 个区间、`scripts/legacy/fetch_cbg_api.ps1` 的 82 个旧 ID）属死代码/历史遗留，已归档到 `scripts/legacy/`，不再参与现行链路。
- **映射到藏宝阁**：藏宝阁区服列表字段 `server_name` 形如 `X6137 百业争鸣(赛季已开启x天)`，`game_serverid` 即筛选参 `game_compete_serverid`；`shishi-open.json` 已给出 `serverid ↔ X 区服` 对应关系。
- **风险**：该 H5 若改版，静态 JSON 路径可能变化（页面内嵌脚本会把 `163hot` 接口重写到 `w.163.com/h5/stzb/gg/data/*.json`）；脚本已内置备用 163hot 接口，若两者都失效需重新定位，届时更新 `scripts/update-shishi.js` 顶部两个 URL 即可。

## 6. 其他已排除的路径

- 藏宝阁内置「区服选择」：只有征服区服/备战区，无试师标记（`https://cbg-stzb.res.netease.com/js/game_compete_server_list.js`，152 个征服 + 1 个备战区）。
- 藏宝阁「赛季预告」（文章说法）：需要 CBG 登录态，且本质是同一份告示板数据。
- 大神社区网页版「福利&工具 → 告示板」卡：未登录点击无响应，需 App；但其背后 H5（本数据源）不需要。
- GitHub `stzbHelper` / `stzbHelperXc`：走游戏客户端抓包路线，无试师区服查询模块。

## 7. 校验与测试（2026-10-25 优化）

```bash
npm test              # 离线回归 = verify-shishi（8 项：结构/排序/批次覆盖/文档覆盖/读取入口/接线/语法）
                      #            + verify-core（配置单源/runmeta/data 契约/接线/BOM）
npm run verify:live   # 额外联网执行 update-shishi --check（verify-shishi 共 9 项）
```

- 覆盖内容：`shishi-servers.json` 结构（批次并集 = ids、时间可解析、最新批次 < 180 天）、`shishi-open.json`（升序/去重、serverid ↔ xid、count 一致）、`shishi-open-serverids.txt` 一致、白名单 md 计数与全部 ID 覆盖、`lib-shishi` 不走兜底、5 个采集脚本接线、8 个 JS `node --check`、ps1 语法解析（`scripts/` 根目录 6 个；`scripts/legacy/` 由 verify-core 与 CI 递归覆盖，`npm test` 与 CI 另做 BOM 检查）；
- 冒烟：`powershell -File scripts/find-all.ps1 -SkipCollect -SkipReport` → 合并 186 个号、退出码 0（不触网）；
- 实测边界：藏宝阁列表接口未登录返回 `SESSION_TIMEOUT`，**真实采集必须登录**（`.cbg-profile` 会话过期时 api-collect 会开浏览器等人登录）；白名单刷新全程免登录；
- 编码坑：`.ps1` 必须存成 UTF-8 **带 BOM**，否则 Windows PowerShell 5.1 按 ANSI 解析中文注释会报 “The string is missing the terminator” 且输出乱码。本次已给 4 个无 BOM 的 ps1 补齐 BOM；
- 备用源现状：`www.163hot.net` 已停更（实测最新批次 2026/5/06）。静态源失败时会触发 60 天校验并 **fail-closed**，不会把残缺白名单写进仓库；
- 建议节奏：每天 `npm run shishi` 一次即可（试师约 2-3 天一批）；接入 `schtasks` 见第 5 节。
