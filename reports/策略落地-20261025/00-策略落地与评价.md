## 2. 参数与公式（已落成）

```
落地战力 = Σ(完整队 × 档位权重)
         + 0.8 × Σ(只缺宝队 × 档位权重)
         + 0.2 × Σ(缺战法队 × 档位权重)
档位权重 = T0+ 10 / T0 8 / T1 5 / T2- 2
性价比   = 落地战力 ÷ (价格/1000)
```

| 层 | 参数 | 值 | 备注 |
|---|---|---|---|
| L1 池子 | 主档价格 | 1500–2500 | 捡漏线 200–1200 预留但未启用（无数据） |
| L2 列表 | 五星 / S 战法 / 稀世宝物 / 锻造 / 核心将 | ≥90 / ≥22 / ≥12 / ≥15 / ≥2 | 五星、S 战法、稀世在列表二次过滤；锻造（duanzao）只能靠服务端参数；反证见 §7 |
| L3 硬规则 | T0+/T0 缺战法 ≥2 | 整队不计 | 本次把 12 支高档队里缺战法的全部剔掉 |
| L3 硬规则 | T1+ 只缺宝缺 ≥3 件 | 权重再 ×0.3 | 防「14 支只缺宝 = 14 支能玩」的幻觉 |
| L3 硬规则 | 价格 >2000 | 须有完整 T1+ 或 T0 只缺宝 | 否则不推荐（§5 有被拦清单） |
| L3 门槛 | 2 完整 T1+，或 1 完整 + 2 只缺宝 T1+ | 主通道 | 13 个号通过 |
| L3 门槛 | ≥3 只缺宝 T1+ 且 ≥2 支只缺 1–2 件 | 补宝型通道（新增） | 7 个号通过；见 §3 冲突 1 |
| 画像 | 即战 / 均衡 / 补宝 | 阈值见 config | 原策略没给数值，本次补定 |

**真成长（growth）**：只缺宝且缺 ≤2 件、档位 T1+ 的队数。这是补宝型的核心指标——「14 支只缺宝」和「3 支补 1 件就能打」是两种号，排序必须分开。

## 3. 实现中必须拍板的 6 个口径（我的默认选择）

1. **补宝型与门槛冲突（最重要）**：原策略的门槛是「至少 2 支完整 T1 或 1 完整 + 2 只缺宝」，但补宝型的定义恰恰是「0 完整、只缺宝多」——**它永远过不了自己的门槛**。我的处理：新增独立通道 `alt2_baobao`（≥3 支只缺宝 T1+ 且 ≥2 支只缺 1–2 件），与主门槛并列。**需要你确认是否接受「补宝型单独放行」**，否则 X5882 ¥2000、X5791 ¥2300 这类号会被直接埋掉。
2. **T0+/T0 是否算「完整 T1」**：我按「T1+ = T0+/T0/T1」计。否则 X5864 的 T0+ 胖章鱼白算，而榜单实际 T0+ 完整队全库只有 1 支（X5864 这个号）。
3. **硬规则与 0.2 权重的互斥**：原策略既要「T0 缺 ≥2 战法当不存在」又要给缺战法 0.2 权重。本次实测：**T0+/T0 缺战法队全部被硬规则剔掉**，0.2 权重只剩 T1/T2- 在起作用。若想让 0.2 有意义，硬规则阈值应改成 ≥3 或只对 T0+ 生效。
4. **「只缺宝」是否含「也缺战法」的队**：我按严格定义（战法齐、宝物缺）计 onlyGear；两者都缺的归 missTac，只吃 0.2。
5. **画像阈值**：原策略只给了文字（「3–4 支完整」「2 支完整 T1 + 2–3 只缺宝」），我定成：即战 = 完整≥3 且 T1+≥2 且只缺宝≤2；均衡 = T1+ 完整≥2 且只缺宝≥2；补宝 = T1+ 完整≤1 且只缺宝 T1+≥2。
6. **性价比的分母**：用「千元」而不是「万元」，且只对过门槛的候选计算——避免 0 完整队的号靠只缺宝堆分数。

### 6.3 策略内部冲突 / 需要修订的地方

1. **补宝型 vs 主门槛**：已用独立通道解决，但需要你确认（§3-1）。
2. **补宝型 vs 溢价规则**：>2000 的补宝型几乎全被拦（X5791/X5849），而补宝型又天然集中在 2000+。需给补宝型单独定价规则（例如：真成长 ≥3 且「补 3 件宝 ≤ 1000 元」才允许溢价）。
3. **硬规则吃掉 0.2 权重**：T0+/T0 缺 ≥2 战法直接不计，导致「缺战法降权」对高档队失效；这批号实际就是「纸面号」，但权重公式看起来像给了它们机会，会造成误解。建议硬规则只作用于 T0+，T0 保留 0.2。
4. **画像与门槛的先后**：画像用「完整 T1+」定义，但补宝型通道的号 fullT1+=0，画像只能落到「补宝型」；如果未来要「均衡型」包含补宝通道号，需重定义。
5. **门槛的样本量**：186 个号里只有 13 过主门槛，说明「2 支完整 T1」在本价位池是稀缺的；这不是门槛错，但意味着**绝大多数采集结果会被丢弃**，L2 的 60–80 个详情采样量可能不够，需要提高到 120+ 或分档采集。
6. **0.8 系数让「纯补宝型」在战力榜登顶**：X5882 ¥2000（0 完整、10 支只缺宝）战力 36 > X5864（T0+ 完整）33。若目标是「到手即战力」，不应与补宝型共用一张榜；建议补宝型单独用「真成长密度（growth 数 / 缺少件数 / 补件成本）」排序，或把 0.8 降到 0.6–0.7 再对比。

### 6.4 无法用现有数据验证的部分

- **召回**：采集池本身已按「五星≥85 / 稀世≥12」过滤，无法知道 85/12 以下漏了多少好号。必须做 §9 对照采样。
- **上架时间 / 公示期 / 降价历史**：数据里没有这三个字段（`api-collect.js` 未采集上架时间，`accounts-final.json` 每次覆盖写）。原策略里「最新上架/公示期是捡漏高发区」「降价 ≥10% 再进详情」这两条最有价值的部分，**当前完全无法落地**，需要先改采集。
- **核心将命中 ≥2**：列表页只给约 10 个代表武将，且未入 `accounts-final.json` 的列表字段，无法在采集前算。
- **L4 人工复核**：版本武将、宝物词条、公示期状态需要打开页面确认，本轮未做。

## 10. 局限

- 数据 186 条、76 天前快照；结论只能证明排序逻辑，不能证明「哪些号值得买」。
- 上游别名/噪声问题未修（`苟彧` 等 27 支队匹配不到、1,317 张噪声卡计入五星），所以「完整队数 / 五星数」两个输入本身有偏差；本报告同池对比可抵消一部分，但绝对值不可外推。
- `api-collect.js` 的 L2 接线只做了离线解析/过滤验证；真实采集（登录态、限流、翻页、服务端参数是否生效）本次未跑，首次重采请先小批量（`topN` 参数或价格段）验证。
- `accounts-api.json` 原始文件可直接喂给 `strategy-eval.js`（价格按“分”自动归一），但那份数据没有浏览器增强字段，画像/锻造会按“未知”处理。
- `司马懿=晋` 版本覆盖已启用（拦截 72 条魏司马懿伪命中），但晋司马懿队全部缺 ≥2 战法被硬规则剔除，净收益 0——这符合「当前池子里 T0+ 完整几乎不存在」的判断。
- 画像阈值、补宝型通道、溢价规则豁免都是本次补定的，属于**待你拍板**的参数，不是定论。
