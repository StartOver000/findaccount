## 0. 一页结论（TL;DR）

1. **主链路是 `find-all.ps1`**：`api-collect.js → merge-api.js → report.ps1(→ analyze-accounts.ps1 + check-teams.ps1 + plan5-node.js) → recommend.js`（`find-all.ps1:30-48`）。ps1 只承担「编排 + 评分 + 报告拼装」，采集/合并/推荐/组合枚举已在 js 侧。
2. **榜单解析 + 武将归一 + 版本校验 + 落地判断被实现了 7 份**：6 份 ps1（`lib-cbg.ps1:64`、`analyze-accounts.ps1:21`、`check-teams.ps1:50`、`count-teams.ps1:45`、`t0-stats.ps1:45`、`t0-hero-count.ps1:19`）+ 1 份 js（`plan5-core.js:62`）。战法映射表 71 条在 ps1 内出现 **5 次且内容完全一致**（哈希相同，见 §3.2）。
3. **`lib-cbg.ps1` 的"公共库"定位已经失败**：全仓只有 `plan5-v2.ps1:13` 一处 dot-source 它（`grep` 全仓唯一），而 `plan5-v2.ps1` 已被 `plan5-node.js` 取代 → **lib-cbg.ps1 事实上是死代码**。
4. **编码是当前最严重的现实缺陷**：`report.ps1:21` 把 node 的 UTF-8 输出经 Windows PowerShell 5.1 管道转存，导致已交付文档 `docs/找号报告-自用-20260807.md` 的「三、各账号最佳5队规划」段落 **248 / 2565 行全部乱码**（实测）。另有 2 个脚本无 UTF-8 BOM，在 5.1 下中文正则完全失效（实测）。
5. **推荐链路的分数输入是断的**：`recommend.js:41` 读 `data/tmp/analyze-latest.txt`，但**没有任何脚本生产该文件**（`report.ps1:17` 只写 `analyze.txt`），且 `data/tmp/` 被 `.gitignore:4` 忽略；更糟的是 `analyze-accounts.ps1:147` 输出 `¥`(U+00A5) 而 `recommend.js:45` 正则要 `￥`(U+FFE5)，一旦按当前代码重新生成 → 武将分恒为 0。现有分数来自 8/10 手工产出的旧文件（经 5.1 GBK 转换恰好把 U+00A5 变成 U+FFE5）。
6. **权重表有 3 套且互不一致**，榜单实际只有 4 档（T0+/T0/T1/T2-，无 T0-）：`analyze-accounts.ps1:178`（T0+=10/T0=8/T0-=6/T1=3/T2-=1）vs `plan5-v2.ps1:38` 与 `plan5-core.js:179`（T0+=8/T0=7/T1=3/T2-=1，无 T0-）。因此「武将分」与「5队最优评分」不可比。
7. **`find-all.ps1 -BrowserFile` 补漏模式静默失效**：`find-all.ps1:27-28` 把路径拼成带内层引号的字符串再作为单个参数传给 node，`api-collect.js:157` 的 `fs.existsSync()` 必然为 false，且失败不打印任何日志。
8. **可淘汰 7 个脚本**：`plan5-v2.ps1`、`lib-cbg.ps1`、`count-teams.ps1`、`t0-stats.ps1`、`t0-hero-count.ps1`、`fetch_cbg_api.ps1`、`find-accounts-20260807.ps1`（证据见 §6.3）。建议把 `analyze-accounts.ps1` 的评分抽成 `plan5-core.js` 的 `scoreAccount()`，最终只保留 `find-all.ps1` + `report.ps1` 两个 ps1 薄壳。
