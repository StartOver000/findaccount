### 5.3 编码对运行的实际影响

- `.github/copilot-instructions.md` 第 74 行明确要求：“**ps1 必须 UTF-8 BOM 否则中文乱码**（node 输出的日志用英文避免管道乱码）”。仓库实际有 2 个 ps1 违反该要求。
- 其中 `fetch_cbg_api.ps1`（第 43、62-66 行）和 `find-accounts-20260807.ps1`（第 33、37、42、49-52 行）的**中文全部用在功能性正则/字符串里**（`征服赛季X(\d+)`、`(\d+)张五星武将卡`、`¥([0-9,]+)` 等）。Windows PowerShell 5.1 读取无 BOM 文件时按系统 ANSI（简体中文环境为 GBK）解码，UTF-8 字节会变成乱码字符，正则不再匹配实际 UTF-8 页面快照——表现为“解析成功但 0 条候选”。在 pwsh 7 下无此问题。
- `report.ps1` 第 17/19/21 行通过 `powershell`（5.1）调用子脚本并用 `Out-File -Encoding utf8` 落盘；5.1 的 `utf8` 会写 BOM，与当前 `data/tmp/*.txt` 中 BOM 文件吻合。也就是说：**同一仓库里 5.1 与 7 两种宿主、带/不带 BOM 两种源文件、UTF-8 与 GBK 两种输出同时存在**。

### 6.2 从零 clone 后“必然失败/必然受阻”的步骤

1. **`npm run extract` / `npm run analyze` 必然失败**：入口文件在根不存在（第 4.1 节）。
2. **`report.ps1` 在纯净 clone 上首次运行必然失败**：它写 `data\tmp\analyze.txt` / `checkteams.txt` / `plan5.txt`（第 17、19、21 行），但 `data/tmp/` 被 `.gitignore` 忽略且仓库不跟踪（`git ls-files data/tmp` = 0），脚本内没有 `New-Item -ItemType Directory`。当前目录能跑是因为本机已存在 `data/tmp/`（64 个历史文件）。`fetch_cbg_api.ps1:36` 同样写 `data\tmp\cbg_page.html`。
3. **不先人工登录，采集脚本无法完成**：`api-collect.js`、`cbg-detail-extract.js` 依赖 `.cbg-profile` 登录态；clone 中不存在，首次运行会停在登录/验证码等待（或采回空数据被跳过）。
4. **未安装 Playwright 浏览器时**：`chromium.launchPersistentContext` 直接报 “Executable doesn't exist”，必须先 `npx playwright install chromium`（需联网下载，约百 MB 级）。
5. **无 BOM 的 2 个 ps1 在 5.1 下功能失效**：`fetch_cbg_api.ps1`、`find-accounts-20260807.ps1` 的中文正则失配（第 5.3 节）；若用 pwsh 7 则正常。
6. **`npm ci` 未联网必然失败**；lock 与 package.json 本身一致，问题只在网络与私有环境。
7. **`.vscode/settings.json` 不可移植**：写死 `d:\WorkSpace\率土之滨`，声明 MCP 服务器 `mcp-server-filesystem` / `playwright-mcp` / `mcp-server-sqlite`，其中 sqlite 指向 `data.db`——该文件不存在（`Test-Path data.db = False`）。
8. **文档链路不闭环**：无 README；`docs/选号计划-从零开始.md` 是“在固定浏览器页面 a993380d 上手工操作”的流程，不可脚本复现；SKILL.md 的 6 个仓库内链接全部失效（第 3.6 节）。
9. **跑 `find-all.ps1` 会改写仓库**：`api-collect.js` 写 `data/accounts-api.json`、`merge-api.js` 写 `data/accounts-final.json`、`report.ps1`/`analyze-accounts.ps1` 写 `docs/accounts-report.md` 与 `docs/找号报告-*.md`、`recommend.js` 写 `docs/最终购买建议-*-自动.md`。复现实验会污染工作区，必须在副本中执行。

### 6.3 结论

- **语法层面**：仓库是自洽的（0 语法错误），`node --check`/Parser 不足以发现问题，问题集中在数据口径、重复定义、入口路径与运行前置。
- **“从零 clone 能跑通”不成立**：即使网络与 CBG 登录态齐备，也需要至少 4 处人工修补（创建 `data/tmp`、安装 Chromium、修正 package.json 入口或改用 `scripts/find-all.ps1`、确认 ps1 宿主/编码），其中第 1/2 条在任何环境下都会复现。
- **数据结论可复现性尚可**：`accounts-final.json` 与 `accounts-api.json` 已提交且可解析，`plan5-core.js` 纯计算部分只依赖 `docs/队伍强度排行榜.md`（已提交），因此“对现有快照重新算分/规划”可以在 clone 中离线复现；但无法复现“实时采集”这一环。
