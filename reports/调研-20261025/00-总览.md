## 0. 摘要

这是一套**单人维护、约 3,000 行、以「榜单匹配 + 采集」为核心的个人决策工具链**：Playwright 带登录态直采藏宝阁 API → 按《队伍强度排行榜》做武将/战法/宝物落地判断 → 生成购买建议。链路是通的，历史上也确实跑出过结论，但**评估模型存在系统性缺口，当前结论不能直接采信**。

### 关键数字

| 指标 | 实测 | 含义 |
|---|---:|---|
| 代码规模 | 12 `.js` + 12 `.ps1` = 2,982 行 | 脚本量不大，但规则重复 7 份 |
| 榜单队伍 | 速览 106 支 → 实际解析 **101** 支 | T1 有 5 支只有标题无配置，被静默丢弃 |
| **真正可评估的队伍** | **63 / 101（62%）** | 12 支被整队跳过 + 21 支武将名在数据中不存在 + 5 支版本标记永不产出 |
| **T0+ 可评估** | **4 / 10** | 变种王异刀、庞统蜀步、九伐队、张飞流氓直接不评估 |
| 账号数据 | 186 条 = 117 浏览器（8/7）+ 69 API（8/10） | 数据已过期约 **76 天** |
| 分析回合静默丢号 | **186 → 163（丢 23 个）** | 按 `server-price` 去重，误伤同服同价的不同账号 |
| 全库「完整落地」队 | 111 支：T0+ **1** / T0 **1** / T1 45 / T2- 64 | 结论天然倒向 T1/T2-，高档队几乎判不出来 |
| 五星卡噪声 | 1,317 / 13,236 张是侍卫/陶渊明等 | 33/129 个 API 号靠噪声才够「五星≥85」 |
| 评分权重 | 文档 1 套、analyze 1 套、plan5 1 套，**三套并存** | 同一账号在不同产物里分数不可比 |

### 一句话结论

**采集层基本可用；评估层的「榜单 → 账号」翻译层（版本/别名/噪声/去重）断了，导致可评估范围只剩 62%，且高档队伍（T0+ 只剩 4/10）大面积判不出来——所以「完整队数」「武将分」「最优 5 队」这三个核心指标目前失真，「链接/价格/武将库清单」可用。** 另有 2 个交付物级事故：已交付的 `docs/找号报告-自用-20260807.md` 第三章整段乱码；`npm run extract/analyze` 必然失败。

| 阶段 | 记录数 | 关键形态 | 坑 |

## 3. 评估模型：五层实现与现实行为

### 3.1 榜单解析（`plan5-core.js:62-104` = `lib-cbg.ps1:64` = 另 5 份 ps1 副本）

- 以 `docs/队伍强度排行榜.md` 的「速览」表为权威名单，再按 `## 档位` / `### 队伍` / 三行武将表解析。
- 实测：**106 支（T0+10 / T0 20 / T1 35 / T2- 41）→ 只解析出 101 支**（T1 的 31–35 号「王异法刀/变种钱步/多马队/丑刀/沙魏马」只有标题，无武将表，被丢）[A]
- 榜单本身有重名：`属性刀` 同时出现在 T0 与 T2- [B]；OCR 错字 `苟彧`（正确为荀彧）出现 6–7 次，数据里 0 次 [A]

### 3.2 武将匹配：版本/别名层（最脆弱的一层）

实现：`HERO_SPECIAL`（hero_id→阵营，`merge-api.js:20-32`）+ `NormalizeMap`（17 条异名归一）+ `VersionReq`（17 条版本要求），三表在 JS/PS 里共 7 份副本。

实测不可匹配原因分布（101 支中 38 支结构上无法匹配任何账号）[A]：

| 原因 | 队数 | 例 |
|---|---:|---|
| 含 `司马懿`/`弓诸葛` 被整队跳过（`plan5-core.js:176,208`） | 12（含 **4 支 T0+**） | 变种王异刀、庞统蜀步、九伐队、张飞流氓 |
| 武将名在 186 个号中根本不存在（别名/OCR/新版武将缺口） | 21 | `苟彧`(6)、`冯嫒`、`新垣曲`、`XP陆逊`、`关妹`、`春华`、`群绍`、`月英`、`马妹`、`汉刘璋`、`大小乔`、`关张`、`凡突骨`、`群吕`、`汉董卓`、`弓诸葛` |
| 版本标记永远不会被生产（`弓吕`要`弓`、`新黄盖`要`新`，`merge-api.js:73` 的 marks 只产出 阵营+极+赛季） | 5 | 变种黄盖刀、袁术网红、黄盖法刀、胡芳网红、龙虎骑 |

→ **可评估队伍 63/101；T0+ 仅剩 4/10（三曹队、三马队、胖章鱼、曹彰物理骑）。**

> 文档要求的是「同名异版本武将必须校验」，代码对司马懿/弓诸葛的选择是「整队不评估」——这不是版本校验，是放弃。补一条 `VersionReq['司马懿']='晋'` 即可解锁 6 个受益账号（Lead 已模拟，T0+ 命中 6 次），但需同时补 `name-camp.json` 的晋阵营与 `HERO_SPECIAL` 的晋 hero_id [A]。

### 3.3 落地判定：战法/宝物别名层

- 战法 101 个 token 中 **34 个未映射**（敛众/鼎足/避其/万箭/胜敌/袭屯/先声夺人/定军山/七擒/重整/白刃…），A/B 写法（`桃园问津（守拙）`）被当成独立 token。
- 宝物 25 个名字中 **9 个在账号库中不存在**：`腾蛇`(应螣蛇)、`惊锐`(惊鲵)、`别铭`(别鸣)、`旋阳万伤`(旌阳万仞)、`斩锐`(骁锐) 等 OCR 错词 + `三公/金鸾/隕口/戟` 疑缺。
- 还有一处典型错字：`TacticMap` 键写成 `风仪亭`（应 `凤仪亭`），导致榜单里的 `凤仪亭` 反而查不到。
- 结果：186 个账号里能判「完整落地」的队共 111 支，但 **T0+ 仅 1 支、T0 仅 1 支**（T1 45、T2- 64）[A]——所以自动建议的「完整队数」几乎只能是 T1/T2-。

### 3.4 评分：三套权重并存

| 来源 | T0+ | T0 | T0- | T1 | T2- | 备注 |
|---|---:|---:|---:|---:|---:|---|
| `.github/copilot-instructions.md:29`（项目宪法） | 10 | — | 6 | 3 | 1 | 漏了 T0，且 T0- 已无队伍 → 6 分是死权重 |
| `scripts/analyze-accounts.ps1:178`（武将分） | 10 | 8 | 6 | 3 | 1 | 另对 5 支吃红度队 `/2` 降权 |
| `scripts/plan5-core.js:179`（5 队最优） | 8 | 7 | 缺 | 3 | 1 | 与上一行不可比 |

→ 同一账号「武将分」与「5 队最优评分」来自两套尺子；文档第三套。且 `recommend.js` 排序根本没用分数（见 P0-5）。

### 3.5 排序与输出

- `recommend.js:70-72` 排序键 = `full*1000 + onlyGear*100 + candCount`，**不含武将分、不含价格**，与文件头「完整队数 → 只缺宝 → 可组 → 武将分」和项目规则「短期接近时优先便宜」都不符。
- `land-stats.js:27` / `plan5-node.js:25` 用 `server-price` 去重（P0-4）。
- `recommend.js:75` 用 `toISOString()`（UTC）生成文件名，Asia/Shanghai 凌晨会写成前一天。
- `recommend.js:41-49` 从 `data/tmp/analyze-latest.txt` 取武将分，但**没有任何脚本生成该文件**（`report.ps1:17` 只写 `analyze.txt`）；且 `analyze-accounts.ps1:147` 输出 `¥`(U+00A5) 而正则要 `￥`(U+FFE5)，只能靠 PS 5.1 GBK 管道的 best-fit 转换「恰好」匹配——换 PS7/UTF-8 输出即武将分恒 0。

## 5. 现在的结论能信多少

| 内容 | 可信度 | 理由 |
|---|---|---|
| 商品链接、价格、区服 | **高** | 直接来自接口字段，未做二次加工 |
| 账号「武将库清单」 | **中高** | 五星过滤后仍有 5.2% 缺阵营标记、1,317 张噪声卡；但武将名本身基本可靠 |
| 完整队数 / 只缺宝 / 缺战法 | **低** | 别名缺口导致高档队判不出，完整队 111 支里 T0+ 仅 1 |
| 武将分排名 | **低** | 三套权重 + analyze-latest 手工文件 + 排序不用分 |
| 最优 5 队规划 | **低** | 司马懿/弓诸葛队直接跳过 + 8/7 权重 |
| 数据时效 | **已过期 76 天** | 最后提交 2026-08-10；藏宝阁商品流动性高，价格/在售状态需重采 |

**结论**：这套工具当前适合「快速拉一批在售号 + 看武将库 + 点链接复核」；**不适合**直接用它输出的「完整队数 / 武将分 / 最优 5 队」做购买决策，尤其是 T0+/T0 档。要恢复决策价值，先做 §7 的 Step 0–1。

## 6. 治理与可复现性

**从零 clone 后必然卡住的位置**（依据 [04](04-静态校验.md) §6）：

1. 无 README → 不知道入口是 `scripts/find-all.ps1`，而 `package.json` 的入口是错的；
2. `data/tmp` 不存在且脚本不建目录 → `report.ps1` 首跑失败；
3. 需要 Windows 桌面 + Playwright Chromium + `.cbg-profile` 登录态（手机验证）→ 无任何文档说明；
4. `data/` 里已有 8/10 快照，但 `git status` 干净会让人误以为数据是新的（实际 76 天前）；
5. 2 个无 BOM 的 ps1 在 PowerShell 5.1 下功能性乱码；交付文档已有成型乱码，但没有校验步骤。

**最小治理建议**：README（入口/前置/数据时效）、`npm run report` 只读链路（跳过采集，用现有 JSON）、`data/tmp` 自动创建、输出编码统一走 Node 写文件（不经过 PS 管道）、`.gitignore` 外置数据或改用 release 附件。
